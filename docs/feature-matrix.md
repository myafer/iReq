# 能力矩阵与取舍

> 这份文件回答一个问题：**同类工具都有的能力里，我们缺哪些、该补哪些、哪些坚决不补。**
> 只按「能不能改变工作流」判，不按「功能清单看起来齐不齐」判 —— 见 `growth-plan.md` 第 8 条。

判断口径：

- **普遍具备**（九成以上的同类工具都有）→ 缺了就是短板，用户会在第一周撞到
- **部分具备**（约一半工具支持，或只在付费档里）→ 做了是差异点，不做也不算残废
- **少数具备**（一两家有，且多是重型工具）→ 只在能顺手做掉时才做
- 来源是各工具公开的功能页与文档的横向比对（2026-11 整理），**不点名**，避免把这份文件写成对标清单

## 1. 已经具备

| 能力 | 我们的做法 |
| --- | --- |
| HTTPS 解密 | 固定根证书 + 按域名动态签叶子证书，跨版本、跨形态复用 |
| HTTP/2 | 走 ALPN 真协商 h2，多路复用逐条记录，不只接受 h1 的降级 |
| 握手失败诊断 | 单独列出反复失败的域名，给原因，一键进「跳过解密」 |
| Mock / 本地响应替换 | 方法 + URL（包含 / 通配 / 正则）+ 域名匹配，可加延迟 |
| 断点（请求 + 响应） | 挂起后改方法 / URL / 头 / body / 状态码，60s 超时自动放行 |
| 重放 | 改任意字段重发，结果入列并与原请求关联 |
| 响应对比 | 重放 vs 原请求，JSON 按结构比、文本按行比 |
| 弱网 / 断网 / 超时 | 按规则命中，实时切断存量隧道 |
| 搜正文、按列排序 | 搜索范围可扩到 body；状态 / 耗时 / 大小可排序 |
| 会话（历史记录） | 清空留档、回看、改名、导出 HAR / JSON |
| HAR 导出 | HAR 1.2，含扩展字段，可直接给别的工具看 |
| 多语言、精简顶栏、命令面板 | ⌘K 既能搜请求也能执行命令 |
| 域名映射 | 只换「连哪台机器」：URL / Host 头 / SNI 仍是原域名，支持 `*` 通配与路径前缀 |
| 导入 HAR | 别人的 HAR 落成一条历史记录，回看 / 重放 / 导出 / 对比全部复用同一套链路 |
| 任意两条对比 | 手选基准优先于重放关系，自己跟自己不比；登录前后同接口最常这么看 |
| 正文按原始字节下载 | 图片 inline、其余 attachment，上游把类型写错时按魔数纠正 |
| 耗时分解 | DNS / TCP / TLS / 等待首字节 / 下载五段分别计时；列表用分段微条、详情用瀑布图，连接复用明确标注 |
| 按接口聚合的性能视图 | 当前筛选下按接口 / 域名给 P50 / P95 / 平均 / 最大 / 错误率 / 传输量 + 最慢请求，点一行即筛到该接口 |
| WebSocket 帧记录 | ws / wss 双向帧按时间线列出：文本解码、二进制记体积、控制帧与分片归位，握手被拒记真实状态码 |
| SSE 消息视图 | 流式响应按规范切成消息（多行 data / 心跳 / id / retry），能看出推了几条、间隔多大 |
| 派生列 | 把响应 JSON 字段 / 响应头提成列表里的一列（支持数组下标与 req. 前缀），改完立即重算 |
| 条件告警 | 状态码 / 域名 / URL / 正文 / 耗时组合匹配，命中推给所有窗口；带冷却、全局限速与静音 |
| 脚本规则 | 沙箱里的 `onRequest` / `onResponse` 同步钩子，改方法 / 地址 / 头 / 状态码 / body；无网络无文件、单次 50ms 超时 |
| 脱敏开关 | 一个开关决定导出与 MCP 输出要不要打码：凭据类头 / 查询参数 / 正文字段，认证头保留 scheme；面板里两栏对照真实流量，**界面永远原值** |
| 会话总览 | 六张卡（请求 / 错误 / 4xx / P50 / P95 / 传输）+ 状态分布 + 域名 + 最慢接口 / 请求；一键复制或下载 Markdown 报告，报告里的 URL 走脱敏配置 |

## 2. 普遍具备但我们缺 —— 必做

A 批（域名映射 / 导入 HAR / 任意两条对比 / 正文另存）已在 1.3.13 完成；B 批（耗时分解 / 性能视图 / WebSocket 帧 / SSE 消息）
已在 1.3.14–1.3.15 完成。**这一栏目前是空的** —— 同类工具普遍有的能力已经补齐，再往下走是第 3 节的差异点。

## 3. 部分具备 —— 做了是差异点

| 能力 | 判断 | 批次 |
| --- | --- | --- |
| **gRPC / Protobuf 解析** | 需要描述文件或反射，投入产出比取决于用户里 gRPC 的比例 | C（低优先） |

## 4. 明确不做

| 不做 | 理由 |
| --- | --- |
| **macOS 签名与公证** | 需要付费开发者账号与固定流水线，不是代码问题。文档里继续给 `xattr -cr` 的说明 |
| **HTTP/3（QUIC）解密** | 代理模式天然看不见 UDP 上的 QUIC；真做要接管 UDP + 自己做 QUIC 栈，Node 生态里没有能撑住的实现。目前策略是「看得见就记录握手失败，并引导降级」 |
| **免证书的网卡层抓包** | 要特权、要各平台分别写，等于第二个产品；而且和我们「零依赖、一条命令起服务」的定位冲突 |
| **透明代理 / 系统扩展** | 平台专属，且和我们「不签名、不装驱动」的取舍矛盾 |
| **证书固定（pinning）绕过** | 那是客户端侧的事，代理能做的只是「识别出来并告诉你」（已做） |
| **批量压测 / p99 尾延迟** | 有专门工具做得更好。我们提供性能视图（P50 / P95 / 慢请求 Top）就够，不承诺压测 |
| **脚本开放网络与文件** | 一旦开放，脚本就能把抓到的流量发出去，信任模型崩了。只给纯函数式钩子 |

## 5. 排期

| 批次 | 内容 | 主题 |
| --- | --- | --- |
| **A** | 域名映射、导入 HAR、任意两条对比、响应体另存 / 图片预览 | 补齐短板，都是「每天都会用到」的 |
| **B** | 全部完成：耗时分解、性能视图、WebSocket 帧、SSE 消息视图（见第 1 节） | 从「能看」到「看得懂」 |
| **C** | 脚本规则 / 派生列 / 条件告警已完成；只剩 gRPC 视图（低优先，按反馈决定） | 从工具到平台 |
| **D** | 脱敏、会话总览 / Markdown 报告已完成；待做：反向代理、脚本模板 + WS 钩子、请求标注（见第 6 节） | 交给 agent，把结论交出去 |

每批都按同一套纪律走：先写自检，再写实现，全套回归绿了才发版；新增能力必须同时更新
`README(.zh-CN).md` 的能力表、`docs/api(.zh-CN).md` 的接口、以及 `docs/development(.zh-CN).md` 的自检清单。

## 6. 2026-11 竞品动向 —— 下一批候选（D 批）

A/B/C 三批做完之后重新横向扫了一遍（公开 changelog / 功能页，2026-11 中旬）。这一轮变化集中在
**「把界面交给 agent」**和**「把结论交出去」**两件事上，而不是再加几个查看器。

| 动向 | 对手怎么做的 | 我们缺什么 | 成本 |
| --- | --- | --- | --- |
| **给 AI / agent 用** | 无窗口模式 + MCP server：agent 能读流量、放行断点、重放、diff、改设置、导出多种格式；另一家还带「给模型的输出先脱敏」与 token 管理页 | MCP 我们早就有（14 个工具 + 只读令牌 + 审计，`bin/ireq.js start` 本来就是无窗口的），**这一项其实不缺**；缺的只是「给模型前先脱敏」，已在 1.3.17 补上 | 已完成 |
| **会话总览** | 卡片式总览：带宽、响应时间分布、内容类型、按域名错误、最大响应，点卡片跳到请求，可复制成 Markdown，并随会话文件一起导出 | 已完成（1.3.18）：六张卡 + 状态 / 域名 / 最慢接口 / 最慢请求 + 复制与下载 Markdown。差一点：还没随会话文件一起导出 | 已完成 |
| **反代抓服务端** | 反向代理模式：抓打向本机的 webhook / 回调 / 网关请求，规则、断点、脚本照常生效 | 只能做正向代理，服务端收到的请求看不见 | 中 |
| **脚本再往前** | WebSocket 钩子（读 / 改 / 丢 / 主动发消息）+ 十几个现成模板 + 可过滤的脚本日志面板 | 只有 HTTP 同步钩子，无模板，日志只留最后 3 条 | 中 |
| **分享前脱敏** | 导出 / 交给模型前把 Authorization、Cookie、token 打码 | 已完成（1.3.17）：导出 / MCP / `redact=1` 三处出口统一走同一套规则 | 已完成 |
| **请求标注** | 给请求加注释、颜色、置顶；团队共享会话 | 只有历史记录整体导出，没法「标出那一条并写一句结论」 | 低 |
| **协议解码广度** | gRPC / Protobuf / MessagePack / Socket.IO / SignalR | 只有 JSON / 文本 / 图片嗅探 | 高（按反馈） |

判断依据没变：只做「能改变工作流」的。D 批执行顺序调整为
**脱敏（已完成）→ Markdown 报告 / 会话总览 → 反向代理 → 脚本模板 + WS 钩子 → 请求标注**；
gRPC 仍然挂在最后，等有真实诉求再动。

> 补充（2026-11-15）：这一节最初把「MCP 接入」列成缺口是**查错了** —— `src/mcp.js` 早就在（14 个工具、
> 只读 / 读写令牌、审计、stdio 桥），`bin/ireq.js start` 本身就是无窗口运行。真正缺的是给模型的那一份
> 内容没有脱敏，所以这一批直接做了脱敏而不是重做 MCP。
